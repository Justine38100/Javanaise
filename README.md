## Architecture

The project follows a standard Maven directory structure:

```text
src/main/java/      application code
src/test/java/      JUnit 5 tests
pom.xml
```

Application code organization:

- `src/main/java/jvn/core`: Javanaise version 1 core, including shared objects, the local server, the coordinator, and RMI interfaces.
- `src/main/java/jvn/proxy`: transparent version 2, using a Java dynamic proxy.
- `src/main/java/jvn/annotations`: `@JvnRead` and `@JvnWrite` annotations used by the proxy.
- `src/main/java/irc/model`: IRC application's domain model (`Sentence`, `SentenceItf`).
- `src/main/java/irc/version1`: IRC version 1 application, with explicit locks.
- `src/main/java/irc/version2`: IRC version 2 application, with a transparent proxy.

## Maven

The project contains a minimal `pom.xml`:

- `groupId`: `fr.m2.sar`
- `artifactId`: `javanaise`
- `version`: `1.0-SNAPSHOT`
- Java version: 17

The project uses JUnit 5 for testing. Maven compiles the application code and tests, then automatically runs the test classes with the Surefire plugin.

## RMI Configuration

By default, Javanaise uses the following local configuration:

```text
jvn.coord.host=localhost
jvn.coord.port=1099
jvn.coord.name=Coordinator
```

These values can be changed using Java properties:

```bash
java -Djvn.coord.host=machine-coordinateur \
     -Djvn.coord.port=1099 \
     -Djvn.coord.name=Coordinator \
     -cp target/classes irc.version2.Irc2
```

Or with environment variables:

```bash
export JVN_COORD_HOST=machine-coordinateur
export JVN_COORD_PORT=1099
export JVN_COORD_NAME=Coordinator
```

Available parameters:

- `jvn.coord.host` / `JVN_COORD_HOST`: host running the coordinator's RMI registry.
- `jvn.coord.port` / `JVN_COORD_PORT`: RMI registry port.
- `jvn.coord.name` / `JVN_COORD_NAME`: RMI name under which the coordinator is published.
- `jvn.rmi.server.host` / `JVN_RMI_SERVER_HOST`: address advertised by the RMI object exported on the current machine.

The last parameter is important when using different machines. It allows other machines to correctly call back to the coordinator or a local server.

## Manual Startup

Stop any existing RMI / Javanaise processes:

```bash
pkill -f rmiregistry
pkill -f 'jvn.core.JvnCoordImpl'
pkill -f 'irc.version1.Irc'
pkill -f 'irc.version2.Irc2'
```

Compile:

```bash
mvn compile
```

Start the RMI registry:

```bash
rmiregistry -J-Djava.class.path=target/classes &
```

Start the coordinator locally:

```bash
java -cp target/classes jvn.core.JvnCoordImpl
```

Start the coordinator with an explicit configuration:

```bash
java -Djvn.rmi.server.host=machine-coordinateur \
     -cp target/classes \
     jvn.core.JvnCoordImpl \
     --host machine-coordinateur \
     --port 1099 \
     --name Coordinator
```

In another terminal, start an IRC version 1 client:

```bash
java -cp target/classes irc.version1.Irc
```

Or start an IRC version 2 client with a dynamic proxy:

```bash
java -cp target/classes irc.version2.Irc2
```

From another machine, specify where the coordinator is running:

```bash
java -Djvn.coord.host=machine-coordinateur \
     -Djvn.coord.port=1099 \
     -Djvn.coord.name=Coordinator \
     -Djvn.rmi.server.host=machine-client \
     -cp target/classes \
     irc.version2.Irc2
```

Example with several computers on the same Wi-Fi network:

```text
Justine's machine: 192.168.172.36
Lisa's machine:    192.168.172.136
Adrien's machine:
```

In this example, the RMI registry and coordinator are running on Justine's machine.

On Justine's machine, compile the project and start the RMI registry:

```bash
mvn compile
rmiregistry -J-Djava.class.path=target/classes &
```

Still on Justine's machine, start the coordinator:

```bash
java -Djvn.rmi.server.host=192.168.172.36 \
     -cp target/classes \
     jvn.core.JvnCoordImpl \
     --host 192.168.172.36 \
     --port 1099 \
     --name Coordinator
```

If the coordinator is already running, first run: `rm jvn-coordinator.snapshot`.

On Justine's machine, start the first client:

```bash
java -Djvn.coord.host=192.168.172.36 \
     -Djvn.coord.port=1099 \
     -Djvn.coord.name=Coordinator \
     -Djvn.rmi.server.host=192.168.172.36 \
     -cp target/classes \
     irc.version2.Irc2
```

On Lisa's machine, start the second client:

```bash
java -Djvn.coord.host=192.168.172.36 \
     -Djvn.coord.port=1099 \
     -Djvn.coord.name=Coordinator \
     -Djvn.rmi.server.host=192.168.172.136 \
     -cp target/classes \
     irc.version2.Irc2
```

Here, both clients connect to the same coordinator, `192.168.172.36:1099/Coordinator`, but each advertises its own address using `jvn.rmi.server.host`.

## Tests

The tests use JUnit 5.

Run all tests:

```bash
mvn test
```

Run only the `JvnObjectImpl` state machine test:

```bash
mvn -Dtest=JvnObjectImplTest test
```

Run only the coordinator test with mock servers:

```bash
mvn -Dtest=JvnCoordImplTest test
```

Run only the integration test in a single JVM, using a real RMI registry, coordinator, and local server:

```bash
mvn -Dtest=JvnIntegrationTest test
```

Run only the multi-JVM E2E tests:

```bash
mvn -Dtest=JvnMultiJvmIntegrationTest test
```

## E2E Tests

The multi-JVM E2E tests launch real Java processes. They start a real `rmiregistry`, a real RMI coordinator, and real Javanaise clients (the entities are not mocked).

They verify:

- creating and reading a shared object;
- concurrent writes from two clients;
- a load test with 2 clients x 1000 messages;
- failure of a client holding a write lock;
- failure of a proxy client after a write;
- coordinator failure and restart, with recovery from the snapshot.

Command:

```bash
mvn -Dtest=JvnMultiJvmIntegrationTest test
```

Scenarios tested in `JvnMultiJvmIntegrationTest`:

- `twoClientsShareOneObject`: one client writes a value to a shared object, then another client reads it. The test verifies that two different JVMs see the same Javanaise object.
- `twoClientsAppendMessagesWithoutLoss`: two clients each append 1000 messages to the same shared object. The verifier then reads the object and checks that all 2000 messages are present.
- `deadWriterDoesNotBlockFutureWriter`: a client becomes the writer, then stops abruptly without calling `jvnTerminate`. A second client then requests a write lock. The expected result is that the coordinator detects the failure with a `RemoteException`, removes the dead writer, and grants the lock to the second client.
- `proxyWriteSurvivesClientCrash`: a client writes using the proxy version, then crashes immediately afterward. The test verifies that another client can still retrieve the value because the proxy saved the state with the coordinator after the `@JvnWrite` call.
- `coordinatorRestartReloadsSnapshotAndClientReconnects`: the coordinator is killed and restarted with the same snapshot file. The client then forces a reconnection and verifies that the object and its state have been restored.

Purpose of the E2E files:

- `src/test/java/jvn/e2e/JvnMultiJvmIntegrationTest.java`: orchestrates the Java processes.
- `src/test/java/jvn/e2e/utils/model/SharedText.java`: shared object used by the tests.
- `src/test/java/jvn/e2e/utils/onejvm/E2EWriterClient.java`: writes a simple value.
- `src/test/java/jvn/e2e/utils/onejvm/E2EReaderClient.java`: reads and verifies that value.
- `src/test/java/jvn/e2e/utils/multijvm/E2ELoadCreatorClient.java`: creates the object used in the load test.
- `src/test/java/jvn/e2e/utils/multijvm/E2ELoadAppenderClient.java`: appends 1000 messages.
- `src/test/java/jvn/e2e/utils/multijvm/E2ELoadVerifierClient.java`: verifies all 2000 messages.
- `src/test/java/jvn/e2e/utils/failures/E2EDeadWriterClient.java`: creates an object, becomes the writer, then stops abruptly.
- `src/test/java/jvn/e2e/utils/failures/E2EWriteAfterDeadWriterClient.java`: verifies that a new writer can write after the previous writer fails.
- `src/test/java/jvn/e2e/utils/failures/E2EProxyWriteAndCrashClient.java`: writes through the proxy, saves the state, then simulates an abrupt client failure.
- `src/test/java/jvn/e2e/utils/failures/E2EProxySavedStateReaderClient.java`: reads the state saved by the proxy after the writer fails.
- `src/test/java/jvn/e2e/utils/failures/E2ECoordinatorRecoveryClient.java`: writes a value, waits for the coordinator to restart, then verifies reconnection and state recovery.
